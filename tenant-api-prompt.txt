# DeskNu — Convert Existing Laravel API into a Multi-Tenant SaaS Platform

You are working on an existing DeskNu Laravel application.

The backend API has already been developed.

Your task is to **carefully convert the existing application into a production-ready multi-tenant SaaS platform** while preserving all existing functionality.

This is NOT a greenfield rewrite.

You must first understand the existing application and then incrementally refactor it.

# 2. PRIMARY OBJECTIVE

Convert the existing DeskNu system into:

> A secure multi-tenant SaaS ticket support platform where each tenant has completely isolated data, users, customers, tickets, departments, settings, API credentials, integrations, and billing/subscription information.

The system must support:


Tenant A must NEVER be able to access Tenant B's data.

# 8. TENANT ISOLATION

Tenant isolation is one of the highest-priority requirements.

Implement a consistent tenant context mechanism.

Every authenticated tenant request must resolve:

```text
Current Tenant
```

Then all tenant-owned queries must be scoped to that tenant.

For example:

```php
Ticket::query()
    ->where('tenant_id', $tenantId)
```

But do NOT scatter unsafe manual tenant checks everywhere if a cleaner architecture can be used.

Use appropriate combinations of:

* Tenant context
* Middleware
* Policies
* Model scopes
* Services
* Repository-level enforcement
* Global scopes where appropriate

The architecture must make accidental cross-tenant queries difficult.

---

# 9. NEVER TRUST tenant_id FROM THE CLIENT

This is critical.

Do NOT allow a normal tenant user to send:

```json
{
  "tenant_id": 2
}
```

and access Tenant 2.

Tenant context must come from authenticated identity or API credentials.

Client-provided tenant_id must never override the authenticated tenant.
